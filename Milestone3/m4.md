# Part 1 — Understand the Milestone

### 1.1 What Exactly Needs to be Built
Milestone 4 focuses on **Platform Administration, Oversight, Analytical Aggregation, and Data Reporting**. The goal is to provide system administrators with full visibility over platform operations, user engagement, recycling metrics, and volunteer activities, while providing enforcement tools to ensure platform safety and compliance.

The major features to build include:
1. **Admin Analytics Dashboard Engine:** Aggregating real-time and historical platform metrics:
   - Total registered users, active user counts, and role breakdown (Volunteers, NGOs, Admins).
   - Waste pickup statistics (Total pickups, pending vs. completed pickups, total weight collected, CO₂ reduction in kg).
   - Volunteer engagement statistics (Active opportunities, application counts, total volunteer hours).
   - Recycling breakdown by waste material (Plastic, Paper, Glass, E-Waste, Organic) with month-over-month growth calculations.
2. **Administrative Controls & Enforcement System:**
   - Account governance: Ability to search, filter, view details, suspend, unsuspend, and update user roles.
   - User session revocation upon suspension.
   - Content moderation: Ability to inspect, flag, suspend, or delete inappropriate volunteer opportunities and posts.
   - Access control middleware enforcing strict `Admin` permissions across all administrative endpoints.
3. **Audit Logging & System Oversight (`AdminLogs`):**
   - An immutable audit logger tracking every administrative action (user suspensions, role modifications, post deletions, system setting updates).
   - Detailed metadata recording for each action (admin ID, target entity type, target ID, action description, IP address, user agent, before/after state diffs).
4. **Analytical Reporting & Export Engine:**
   - Multi-format downloadable reports (CSV, Excel `.xlsx`, PDF `.pdf`).
   - Four primary report types:
     1. **Users Report:** User profiles, roles, registration dates, activity status, suspension flags.
     2. **Pickups Report:** Pickup requests, scheduled dates, waste categories, collection weights, assigned pickup agents, status lifecycle.
     3. **Opportunities Report:** NGO opportunities, required skills, duration, applicant counts, status.
     4. **Full Platform Activity Report:** Consolidated platform audit log and cross-module telemetry.
   - High-performance stream-based export infrastructure to prevent Node.js main thread blocking or memory exhaustion on large datasets.

# Part 2 — Backend Architecture

### 2.1 Layered Architecture Overview

The backend follows a strict decoupled multi-tier architectural pattern:

```
[ HTTP Request / Socket Event ]
              │
              ▼
    [ Security Middleware ] ──► (Auth JWT, RBAC Admin Check, Rate Limiter)
              │
              ▼
      [ Input Validator ]   ──► (Express-Validator / Joi Schemas)
              │
              ▼
         [ Controller ]     ──► (HTTP Handling, Request Parsing, Status Codes)
              │
              ▼
           [ Service ]      ──► (Business Logic, Aggregations, Audit Trigger)
              │
              ▼
       [ Data Access ]      ──► (Mongoose Models & MongoDB Aggregations)
```

- **Controllers:** Parse request parameters, validate headers, delegate logic to services, and return standardized JSON responses.
- **Routes:** Define endpoint paths, attach rate limiters, and chain security/validation middleware.
- **Models:** Define Mongoose schemas, field types, validation rules, virtuals, middleware hooks, and compound indexes.
- **Middleware:** Enforce JWT verification, role-based access control, account status verification, request sanitization, rate limiting, and centralized error handling.
- **Services:** Contain business rules, coordinate multi-model transactions, invoke report generators, and execute MongoDB aggregation pipelines.
- **Utils:** Reusable helpers for file formatting (CSV/Excel/PDF), mathematical conversions (CO₂ calculation formulas), and date formatting.
- **Validators:** Schema definitions validating query parameters, pagination arguments, date ranges, and administrative payloads.
- **Socket Gateways:** Real-time event emitters broadcasting platform telemetry and executing administrative force-disconnects.

### 3.1 Collection Specifications

#### 1. `Users` Collection (Modified)
- **Purpose:** Stores user profiles, credentials, role permissions, and administrative account state.
- **Fields:**

| Field Name | Data Type | Required | Default | Validation / Constraints | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Yes | Auto | Primary Key | Unique User ID |
| `name` | String | Yes | None | Trim, 2-100 chars | Full name of user |
| `email` | String | Yes | None | Unique, Lowercase, Regex email | Unique login email |
| `password` | String | Yes | None | Min 8 chars, Hashed (Bcrypt) | Account password |
| `role` | String | Yes | `'volunteer'` | Enum: `['volunteer', 'ngo', 'admin']` | RBAC Role |
| `skills` | [String] | No | `[]` | Array of strings | Volunteer skill set |

| `suspendedAt` | Date | No | `null` | Valid Date | Timestamp of suspension |

| `createdAt` | Date | Yes | `Date.now` | Immutable Date | Account creation date |

#### 6. `Redesigned AdminLogs` Collection

> [!IMPORTANT]
> **Redesign Rationale:** The original PDF `AdminLogs` schema contained basic fields (`id`, `action`, `user_id`, `timestamp`). This lacks contextual awareness required for enterprise audits. The redesigned schema includes `admin_id` (who performed the action), `target_type` (what object type was altered), `target_id` (ID of the altered object), `ip_address`, `user_agent`, and `changes` (before/after snapshot) for complete audit trail traceability.

- **Fields:**

| Field Name | Data Type | Required | Default | Validation / Constraints | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Yes | Auto | Primary Key | Audit Log ID |
| `admin_id` | ObjectId | Yes | None | Ref: `Users` | Admin who took action |
| `action` | String | Yes | None | Enum: `['USER_SUSPENDED', 'USER_UNSUSPENDED', 'USER_ROLE_CHANGED', 'OPPORTUNITY_REMOVED', 'OPPORTUNITY_RESTORED', 'PICKUP_STATUS_OVERRIDE', 'REPORT_DOWNLOADED']` | Action classification |
| `target_type` | String | Yes | None | Enum: `['User', 'Opportunity', 'Pickup', 'Report']` | Entity affected |
| `target_id` | ObjectId | Yes | None | Dynamic Ref | ID of entity affected |
| `details` | String | Yes | None | Trim, Max 500 chars | Description of event |
| `changes` | Object | No | `{}` | `{ before: {}, after: {} }` | State diff snapshot |
| `ip_address` | String | Yes | `'127.0.0.1'`| IPv4 / IPv6 string | Request IP address |
| `user_agent` | String | No | `""` | Client browser header | Client metadata |
| `timestamp` | Date | Yes | `Date.now` | Immutable Date | Event log timestamp |

- **Indexes:**
  - `{ timestamp: -1 }` — Reverse chronological audit log feed.
  - `{ admin_id: 1, timestamp: -1 }` — Admin activity tracking.
  - `{ target_type: 1, target_id: 1 }` — Specific entity history lookup.

### 4.2 Detailed API Endpoint Specifications

#### Endpoint 1: GET `/api/v1/admin/dashboard/stats`
- **Purpose:** Retrieves high-level administrative KPI metrics (Total Users, Completed Pickups, Pending Pickups, Active Opportunities) along with month-over-month growth trends.
- **Authentication:** Required (Bearer JWT)
- **Authorization:** `Admin`
- **Request Body:** None
- **Query Parameters:** None
- **Response `200 OK`:**
```json
{
  "status": "success",
  "data": {
    "totalUsers": { "count": 1420, "growthPercentage": 8.5 },
    "completedPickups": { "count": 384, "growthPercentage": 12.4 },
    "pendingPickups": { "count": 42, "growthPercentage": -3.1 },
    "activeOpportunities": { "count": 29, "growthPercentage": 5.0 }
  }
}
```
- **Errors:** `401 Unauthorized`, `403 Forbidden`
- **Mongoose Query / Aggregation:** `$facet` pipeline across `Users`, `Pickups`, and `Opportunities` collections matching counts for current month vs. previous month.

#### Endpoint 2: GET `/api/v1/admin/users`
- **Purpose:** Paginated listing of platform users with search, role, and suspension filtering.
- **Authentication:** Required (Bearer JWT)
- **Authorization:** `Admin`
- **Request Body:** None
- **Query Parameters:** `page` (default: 1), `limit` (default: 10), `role` (`volunteer|ngo|admin`), `isSuspended` (`true|false`), `search` (name or email keyword).
- **Response `200 OK`:**
```json
{
  "status": "success",
  "results": 10,
  "pagination": { "total": 1420, "page": 1, "pages": 142 },
  "data": {
    "users": [
      {
        "_id": "64f1a2b3c4d5e6f7a8b9c0d1",
        "name": "Alex Johnson",
        "email": "alex@example.com",
        "role": "volunteer",
        "isSuspended": false,
        "createdAt": "2026-07-15T10:30:00.000Z"
      }
    ]
  }
}
```
- **Errors:** `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`
- **Mongoose Query:**
```javascript
const query = {};
if (search) query.$or = [{ name: new RegExp(search, 'i') }, { email: new RegExp(search, 'i') }];
if (role) query.role = role;
if (isSuspended !== undefined) query.isSuspended = isSuspended === 'true';

const users = await User.find(query).skip((page - 1) * limit).limit(Number(limit)).sort({ createdAt: -1 });
```

# Part 5 — MongoDB Aggregation Pipelines

### 5.1 Pipeline 1: User Dashboard Core Metrics

**Collections Used:** `Pickups`, `WasteStats`, `Applications`

```javascript
// Aggregation for User Dashboard Metrics
const userId = new mongoose.Types.ObjectId(req.user._id);

const startOfCurrentMonth = new Date(new Date().getFullYear(), new Date().getMonth(), 1);
const startOfLastMonth = new Date(new Date().getFullYear(), new Date().getMonth() - 1, 1);

const metrics = await Pickups.aggregate([
  {
    $facet: {
      "currentMonthPickups": [
        { $match: { user_id: userId, createdAt: { $gte: startOfCurrentMonth } } },
        { $count: "count" }
      ],
      "previousMonthPickups": [
        { $match: { user_id: userId, createdAt: { $gte: startOfLastMonth, $lt: startOfCurrentMonth } } },
        { $count: "count" }
      ],
      "totalCompleted": [
        { $match: { user_id: userId, status: "completed" } },
        { $count: "count" }
      ]
    }
  }
]);
```

**Performance & Indexes:**
- Required Index: `Pickups.createIndex({ user_id: 1, createdAt: -1 })`
- Enables index scans for user-scoped time ranges.

### 5.2 Pipeline 2: Recycling Breakdown by Waste Category

**Collections Used:** `WasteStats`

```javascript
const recyclingBreakdown = await WasteStats.aggregate([
  {
    $match: {
      date: { $gte: startOfCurrentMonth }
    }
  },
  {
    $group: {
      _id: "$category",
      totalWeight: { $sum: "$weight" },
      totalCO2: { $sum: "$co2_saved_kg" }
    }
  },
  {
    $group: {
      _id: null,
      grandTotalWeight: { $sum: "$totalWeight" },
      categories: {
        $push: {
          category: "$_id",
          weightKg: "$totalWeight",
          co2Saved: "$totalCO2"
        }
      }
    }
  },
  { $unwind: "$categories" },
  {
    $project: {
      _id: 0,
      category: "$categories.category",
      weightKg: "$categories.weightKg",
      co2Saved: "$categories.co2Saved",
      percentage: {
        $multiply: [
          { $divide: ["$categories.weightKg", "$grandTotalWeight"] },
          100
        ]
      },
      grandTotalWeight: "$grandTotalWeight"
    }
  },
  { $sort: { percentage: -1 } }
]);
```

**Performance & Indexes:**
- Required Index: `WasteStats.createIndex({ date: -1, category: 1 })`
- Drastically speeds up `$match` stage on high-volume waste telemetry collections.

# Part 6 — Reports Module

### 6.1 Export Formats & Library Selection

| Export Format | Selected NPM Library | Selection Justification | Implementation Strategy |
| :--- | :--- | :--- | :--- |
| **CSV** | `json2csv` + Node `Transform Stream` | Lightweight, extremely fast streaming conversion without keeping entire dataset in memory. | Pipe Mongoose Cursor directly to CSV Stream. |
| **Excel (`.xlsx`)** | `exceljs` | Supports styling, custom headers, multiple worksheets, cell formatting, and stream writing (`ExcelJS.stream.xlsx.WorkbookWriter`). | Streaming workbook creation with styled header rows. |
| **PDF (`.pdf`)** | `pdfkit` + `pdfkit-table` | Programmatic PDF creation with tight layout control, dynamic page numbering, footers, and low overhead. | Custom table grid generation piped directly to HTTP response. |

---

### 6.2 Implementation Strategy: Streaming vs Memory Buffer

> [!WARNING]
> Loading large export datasets (e.g., 50,000+ user audit records) into memory using `Array.map()` or `JSON.stringify()` will crash the Node.js process due to Heap Out-Of-Memory errors. Milestone 4 MUST mandate stream-based report generation.

```
[ MongoDB Database ]
        │
        ▼ (Mongoose Cursor .cursor())
[ Document Stream Chunks ]
        │
        ▼ (Node.js Transform Stream)
[ Format Exporter Stream (CSV / ExcelJS / PDFKit) ]
        │
        ▼ (HTTP Pipe .pipe(res))
[ HTTP Response Stream to Client ]
```

#### Code Implementation Example (CSV Streaming Controller):
```javascript
const exportUsersCSV = async (req, res, next) => {
  try {
    res.setHeader('Content-Type', 'text/csv');
    res.setHeader('Content-Disposition', 'attachment; filename="users_report.csv"');

    const cursor = User.find().lean().cursor();
    const json2csvTransform = new Transform({ objectMode: true });

    // Stream transformation logic
    let isFirst = true;
    cursor.on('data', (doc) => {
      if (isFirst) {
        res.write('ID,Name,Email,Role,IsSuspended,CreatedAt\n');
        isFirst = false;
      }
      res.write(`"${doc._id}","${doc.name}","${doc.email}","${doc.role}",${doc.isSuspended},"${doc.createdAt}"\n`);
    });

    cursor.on('end', () => res.end());
    cursor.on('error', (err) => next(err));
  } catch (error) {
    next(error);
  }
};
```

### 7.2 Administrative Middleware Implementation

```javascript
// middlewares/rbac.middleware.js
const AppError = require('../utils/appError');

exports.requireAdmin = (req, res, next) => {
  if (!req.user || req.user.role !== 'admin') {
    return next(new AppError('Access denied. Administrator privileges required.', 403));
  }
  next();
};

exports.ensureUserNotSuspended = (req, res, next) => {
  if (req.user && req.user.isSuspended) {
    return next(new AppError(`Account suspended: ${req.user.suspensionReason || 'Contact support.'}`, 403));
  }
  next();
};
```

### 7.3 Security Measures Checklist

1. **Rate Limiting:**
   - Admin Login: Max 5 requests per 15 minutes per IP.
   - Report Downloads: Max 10 requests per hour per admin user.
   - Standard APIs: Max 100 requests per 15 minutes per IP.
2. **Audit Logging Guarantee:**
   - Automatic execution of `AuditService.logAction()` whenever an admin invokes a write/update operation on users or opportunities.
3. **Data Sanitization:**
   - Prevent MongoDB Query Injection using `express-mongo-sanitize`.
   - Prevent XSS attacks using `helmet` HTTP security headers.
